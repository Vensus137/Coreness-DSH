# The constructor — the page's elements, their values, and the cheap path that adds one

This is the written form of the page's drawable material. It is not a design ideal and not a wish list: every element named here is one the page draws, every value is one the page reads, and the path that adds the next element is the one this file is written to make cheap.

**The one rule, and the path beside it.** A card draws only from the constructor. When an element it needs is absent, the card does not draw a private copy and does not bend a neighbour: it proposes the element (§Adding an element), the proposal is challenged, the element is added here and to the values in the same pass, and only then is it drawn. The rule and the path stand in one breath on purpose: a prohibition without a path is a rule agents work around.

## What this is

The constructor has three parts and nothing else: the **elements** the page may draw, each with its contract; the **values** those elements read, each written once; and the **path** by which a new element joins them.

The reason it exists is a failure the drawing itself produced, kept here because it is the ground of every rule below: five cards drew one status five private ways, so "put it in the middle" was one of the available options rather than an error, and three misses reached the reader through a green gate. The answer is that the middle is written down.

The first element is already in the tree and this file is shaped after it: `plugins/page/client.status.js` — one map of words, one drawing, one place rule in the component's own sheet, one tone derived from the same lookup, one door by which a reason leaves the face for the console. §The first element: Status is that element's contract, written out, so the file teaches by something that exists rather than by an abstraction.

What this file is not: a component library. The elements are the page's own drawing functions and class names as the chunks already carry them; the constructor names them, fixes their contracts and their values, and leaves the drawing where it stands until a card moves it.

**Why it stays, and who keeps it.** This file answers the two things a document must: it says what it is, why it exists and why it stays — the three parts above, and the decision that made the middle written down. It is kept by the sessions that move the code: its place rests on what it is for and on the drawing it describes, never on anyone's authority. And it lives by being updated rather than by being kept: every fact in it is re-read against the code in the pass that moves the code or the fact, which is why it carries no line and no revision. The **permission list** — the class families the page may draw, the family-less names it draws with, and the `var(--coreness-*)` names it declares — stands in `plugins/page/README.md`, where the batch's census reads it, and is not repeated here; this file carries the **contracts** behind those names.

## The elements

> **Read from the committed blobs, not from the working tree** — a plant in a chunk is a lie to any reader of the tree, and this table is what the next element is added against. Every row was taken from the drawing: the registration, the class families each sheet declares, the drawing functions, the platform names each file reads, and the dictionary each carries. A row marked **private** is an element the page draws without the constructor governing it; those marks are named again in §What is not settled here, and the names, owners, sheets and bounds each row carries were checked against the code in the pass that restored this file.

Every row carries five fields, and an element that cannot answer all five is not an element yet: **Who holds these fields: the reader.** A machine argues one of the five — *who owns it* — and that one is held by a reading in the page’s own checks; the rest are the reader’s, so a row that fills one field and leaves four empty is legal by this decision and not by oversight. Holding all five in a runner was refused: it needs two closed vocabularies the tree does not carry — the rooms an element may stand in, and the namespaces, which are the platform’s — so it would mean inventing them and re-answering every row in exchange for a form of *what it is* that stops an empty row while holding no meaning.

| field | what it answers |
| --- | --- |
| what it is | the one thing this element is for, in a sentence, and what it may not become |
| where it may stand | the rooms it may be drawn in — a card head, a card body, a section root, a row, a seat — and the rooms it may not |
| the values it reads | the names of §The values it is allowed to read, and no number of its own |
| the words it may carry | whether its words come from a dictionary, which namespace owns them, and which words are the caller's |
| who owns it | the one chunk that draws it, and what a caller may hand it and never write itself |

**Which of the five a check can read, and which only a reader.** Three are readable from the drawing: **who owns it** (the chunk whose sheet declares the family), **the values it reads** (the names its sheet reads), and **the words it may carry** (the namespace and the keys it holds). One is prose and no check reaches it — **what it is** — and one is a room, read from the drawn tree rather than from the row: **where it may stand**. That split is not a courtesy to the file: the page's own check already reads the first two shapes (*every class family the page draws is the inventory's, and every value a sheet reads is one the page declares*, the census check in `plugins/page/test/client.test.mjs`), so a row whose owner, values or namespace is empty is not a row — it is a sentence, and the inventory does not carry sentences. The split is a decision and not an observation: one of the fields is held by a reading, and it holds the rows that name both a chunk and a class — a row’s owner must carry the family the row names — while a row naming its owner in prose (`the section’s chunk`, the platform, or nothing at all) is skipped and stays the reader’s, which the reading says in its own words where it stands. A second reading once stood beside it, holding every `--coreness-*` name a row writes to a name the page declares; it was withdrawn because it held nothing — no row writes such a name, so its only evidence was a planted defect, and a check whose sole evidence is a plant is a claim about the future — and it returns with the first row that writes a declared name.

**The rows name sheets and dictionaries and count neither.** A count of a sheet is a reading rather than a fact of the drawing: it moves with every edit and no check of this tree holds it. The per-sheet rule counts and the dictionary-key counts these rows once carried were read against a window that is gone — a counting rule no file records and an instrument nothing in this tree carries — so they are not carried here, because a number no command prints lies silently. A count that is asked for is printed where it is taken: `node scripts/page-css-read.mjs --chunks` prints every chunk's own rule count beside the rule it counts by (a rule is one line of a sheet carrying `{`, its first `{` opening it, the selector every line since the last `}` or the last line carrying `{`, comments off first, and only the chunk's own sheet read), and the dictionaries' key counts are printed by no command at all, so no key count stands in these rows.

The row that matters most is **a status**: one element, one contract, and two ways of drawing it in this tree — the channelled one `client.provider.js` pulls, and the entry's own.

The two genres are part of the inventory and not a style: a **state** stands without a press, in the state's room in a card head; **news** is the answer to a press, in the strip of the card the press was made in, and where that card is gone the word stands nowhere rather than in a neighbour (`plugins/page/README.md`).

## The values

**What the platform gives.** The platform's token sheet is one string and it declares **403 names**: `alias-*` 107 (the semantic colours and the `alias-state-{business,error,idle,success,warn}-{primary,secondary,tertiary}` tones), `static-*` 77 (the raw palette), `font-*` 182 — among them **30 type pairs**, each a `-font-size` name with its `-line-height` beside it — `radius-*` 6 (`xs`, `sm`, `md`, `lg`, `xl`, `panel`), `shadow-*` 4, `elevation-*` 5, and a handful of `menu-*`, `focus-*`, `mask-*` and gradient names. The page reads **35 distinct** `--dsw-*` names over its own sheets: `--dsw-alias-label-primary` 24 times, `--dsw-alias-label-tertiary` 24, `--dsw-alias-label-secondary` 14, `--dsw-radius-md` 10. The 403 is printed by `scripts/harness.mjs cat` over the platform's own theme client, and the page's own names and their counts by the page's own value reader, `node scripts/page-css-read.mjs --values`.

**What this layer adds, and why each name exists rather than borrowing one.**
- **Spacing.** The sheet names no distance at all: a filter over all 403 names for `space`, `gap`, `padding`, `margin` or `size` returns font sizes and line heights and nothing else. The page carries the distances as numbers — over the seven sheets that carry one (`client.hold.js` has none), **273 declarations whose value carries a px number, 19 of them through a `var(`** — and the same reading yields **32 distinct px values**, of which **ten stand exactly once** — 64, 120, 140, 188, 220, 240, 260, 320, 440 and 999 — the rest being distances the page repeats. Both are printed by `node scripts/page-css-read.mjs --values`, the page's own value reader. The reading is over the sheets' rules with their comments off: a line of prose inside a comment is not a declaration, and counting one as a declaration is how a value nobody draws enters a scale. Colour is channelled through the platform's names; distance is not channelled at all. This is the whole reason the spacing family exists, and its names are taken from the drawing.
- **Tones.** The tones the status uses are the platform's own colour names — `--dsw-alias-label-tertiary` for `plain`, `--dsw-alias-state-success-primary` for `done`, `--dsw-alias-state-error-primary` for `fault` — the first in the component's own sheet (`plugins/page/client.status.js`), the other two where the page paints every state's sentence (`plugins/page/client.js`) — and what this layer adds is not a colour but the **tone names themselves**: `plain`, `done`, `fault` are the page's own and are the vocabulary a card may use; a card never names a colour.
- **The status's place.** `margin-left:auto` in the component's own sheet (`plugins/page/client.status.js`) is a place, not a colour, and the platform has no name for it. It stays the page's own, in the element's own sheet, so that no section carries a place rule of its own.
- **The lifetime of a temporary answer.** `plugins/page/client.hold.js` holds one number — `NOTE_HOLD_MS = 5000`, with the reason written beside it the platform's own 4000 ms and `min(8000, max(3000, 80 × characters))`, the user's rule that it is the same everywhere and 3–5 s, and the price of the top of that range) — and hands it out through `holdOf`. It is a value of the same kind as the status's place: the platform has no name for a lifetime, the number is a choice, and the choice belongs in one place rather than in each section that draws a note. Three chunks pull it (`client.mcp.js`, `client.provider.js`, `client.gate.js`), and the batch holds that no chunk writes a number of its own.
- **Bounds that are decisions.** A few numbers are bounds rather than spacings and each is read by one element: the text box's floor and the drop-down's ceiling (`plugins/page/README.md`), the news strip's reserved width is one named value, `--coreness-news-strip` (`plugins/page/client.js`), read by the strip both sections wear (`.coreness-answer`, `plugins/page/client.js`), with a second `160px` standing as a column floor in the Qoder's grid (`client.provider.js`) — and the panel's column. They are named in the same layer, one name each, so that a reader can see they are choices and not oversights.
- **The one raised surface, and its exception.** `--coreness-elevation` is declared once — `:root{--coreness-elevation:0 12px 32px #0000002e}` (`plugins/page/client.js`) — and read by the three surfaces that float over the page: the MCP row menu (`client.mcp.js`), the picker's list (`client.picker.js`) and the credits card (`client.credits.js`). The platform's sheet holds 5 `elevation-*` and 4 `shadow-*` names and **no token anywhere in it carries that colour**; its nearest, `--dsw-shadow-lv3`, is this page's own geometry at half the alpha plus two rings the page does not draw, so borrowing it would change how three surfaces look, and a page-owned *colour* name would break the rule above — colour is channelled through the platform's names while distance is what this layer adds. The decision taken: **the name stays and its colour stays inside it, wholesale** — one place, one name, nothing visible changed — and the exception is stated rather than smoothed: *the three raised surfaces keep a shadow the platform's scale has no equal for.*
- **One shape the radius scale does not carry.** The pill's radius, `999px`, stood written twice (`plugins/page/client.credits.js`) and is now one name of the page's own, `--coreness-pill-radius` (`plugins/page/client.js`), read by the bar and its fill — rather than a borrowed `radius-*` step, because the platform's six radii are steps of a scale and a pill is not a step.

**The shape.** Names of the page's own under its own namespace — `--coreness-…`, declared **once**, on the root the page draws into, in the entry's own sheet — and read by every element. An element reads names and never numbers: a number standing in a sheet is a value that has not been named yet, and the fix is one line in the layer, not a discussion. The type scale, the radii, the shadows and the elevation names are **borrowed** from the platform's sheet rather than replaced; the worked example proves the point in one line — `font-size:12px;line-height:18px` in `plugins/page/client.status.js` is exactly the platform's `font-xxs-12` pair, and it is written there as two numbers.

## Where it lives, and why

**The reading, taken from the platform's own source and the package's manifest.** A client chunk is package-local by construction, and a chunk cannot be shared across packages:

- A chunk's identity, its URL, its revision and its file path all hang off the owning package. The client half keys a chunk as `` `${ownerId}/${fileName}` `` and `chunkUrl` derives the URL from the owner's own bundle URL, throwing unless that row's resource is exactly `` `${row.id}/client.js` ``. `require.async` sends any spec not starting with `./` to `import`, and a relative one must match `CLIENT_CHUNK = /^client\.[A-Za-z0-9][A-Za-z0-9._-]*\.js$/` and is fetched as the owner's chunk; a script that registers under any other id is an error.
- The node half serves a chunk from the entry's own directory: `chunkRequest` matches `/plugins/<entry id>/<file>` and requires the exact current-revision URL, and `chunkResponse` reads `join(dirname(record.meta.clientPath), fileName)`, answering 404 when no such file stands there. `CLIENT_CHUNK` is commented "published **package-local** client chunk names accepted by the on-demand route".
- One package carries one client entry. The graph is composed by scanning the host Loader's entries for packages declaring `dsh.client`, and per row the entry is `exports["./client"]` (`clientExportOf`, called at, which throws when `dsh.client` is declared and `./client` is not); the resolved path is `join(dirname(pkgPath), clientRel)`, and the table is keyed by package name.
- What a non-relative `require.async` reaches is an **entry**, not a chunk: `import` answers a seed word, an already-materialised id, or a boot-graph row, and returns that row's exports. A chunk's file can never be named this way.
- **The package's manifest is that shape**: `package.json` `@coreness/dsh`, `"./client": "./plugins/page/client.js"` with the other four exports host-only, the row (`dsh.bundle.patch`, `dsh.client.platform: "web"`), and `bundles/coreness.patch.yml` in its own words — "one row per plugin of this package … one package carries one browser half". There is no `plugins/*/package.json`.
- What the local batch can see is the same shape: the harness materialises the chunk as `` `${MANIFEST.name}/${fileName}` `` in `materialise`, and any non-relative require other than `react` throws in that function's own module table (`plugins/page/test/client.test.mjs`).

**Therefore the constructor lives inside the drawing package**: the values stand in the entry's own sheet beside `plugins/page/client.js`, and the contracts stand in this file, next to the drawing they govern. A chunk of its own for them — `client.constructor.js`, pulled relatively by every section chunk the way the picker, the hold and the status are pulled -- was proposed and **never built**: the values it was to hold are declared in the entry's sheet, and this file describes the tree as it stands rather than the shape it was written against. Nothing in the page depends on that chunk.

**The road not taken, and its price.** A package of its own — `dsh.client` plus `exports["./client"]` — would be reachable by `require.async('@coreness/dsh-constructor')` and would hand back its entry's exports. It costs three things: a second row in the profile's bundle, against "one bundle for a profile" (`package.json`); an **asynchronous** arrival on the page's own path, which a value layer every element reads cannot wait on; and a check that cannot see the road at all, because the harness refuses every non-relative require but `react` (`plugins/page/test/client.test.mjs`) — a green over a road nothing exercised. The last price is the one that decided it.

## Adding an element

A card that needs an element does three things and no more:

1. **Look in the inventory.** If the element stands there, draw it and read its values; a private copy of an element that exists is a defect of the card, not a feature of it.
2. **If it is absent, propose a row** — the five fields of §The elements, filled: what it is, where it may stand, the values it reads, the words it may carry and their namespace, and who owns it. The proposal is challenged by the skeptic card that follows this one; when it stands, the row joins §The elements and its values join §The values in the same pass, and only then is it drawn.
3. **If a value it needs has no name, add the name** to the value layer — one line in one place, with the reason it exists rather than a borrowed name. **Until the layer stands, the name is written in the same pass that uses it**, so the compliant move is never the violation: a card that needs a distance the layer does not carry adds the name and reads it in one pass, and the review sees a name where it would otherwise have seen a private number.

**The price, said once**: the first element pays for the layer; every element after it pays a row and a name.

**Concretely cheap means**: no new file, no new chunk, no new registration, no new seat, and no check to satisfy beyond the ones already standing. A row and a value, and the next card inherits both. The path is deliberately shorter than the prohibition is broad, because the prohibition is only worth writing while the path is cheaper than the workaround.

**What the path costs, measured**: the price above is the price of an **element inside a section**, and it is cheap by construction — a row, and at most a name. A **section** is not that shape: it costs a chunk, a line in the entry, a row in this inventory and the checks that hold the page's present shape, and that is where such a change spends its minutes. The promise of "no check to satisfy beyond the ones already standing" holds for an element and does not hold for a section.

**The prohibition.** A card draws only from the constructor. An element a card draws privately — its own status, its own spacing numbers, its own colour — is a defect of that card and is named as one in review; the element moves into the constructor in the pass that names it. There is no exemption a card may grant itself: a row that genuinely cannot carry the element is not a licence to draw privately but a proposal owed, and the path below is short on purpose — a card that skips it has chosen the workaround over the path.

## The first element: Status

The contract below is `plugins/page/client.status.js` **as it stands**.

**The map.** `STATUS_WORDS` is the only place a status word or a status tone is written. Its values, each an entry of `{ words, tone }`: `loading`, `unset`, `set` at `plain`; `accepted`, `saved`, `answered` at `done`; `refused`, `unsaved`, `unwritable`, `unread`, `unanswered` at `fault`. The subject is the card's own one word for what the status is about — `Token`, `Node`, `Server`, `Limit`, `Usage`, `Page` — passed into `{subject}` and never written by the card itself. An entry nobody holds draws nothing, so a card with nothing to state carries no status and no reserved box.

**The three-way split.** The state stands on the face; the act stands in the log; the content stands in the card's body. The map carries no act — what is true after a clear is `unset`, not "cleared" — and a reason the face may not carry is not muted but moved: `statusDetail(subject, reason)` writes `${PACKAGE} · ${subject} · ${reason}` to the console, is called **where the answer arrives** and not where the status is drawn, so an attempt that learned nothing is said as many times as it was made, and it is silent for an empty reason.

**The tone.** The sentence takes its colour from the entry's own `tone` field, and the mark takes its own out of `MARK_TONES`: a word is a card's news and a mark is a connection, so the map's `set` turned green would turn `Profile is set` green on the entry's own card. A green mark beside a refusal is therefore not a defect to be checked for — it is a state this element cannot express. `data-status` names the value and `data-tone` the tone, and there is no other way to give the element a colour.

**The place.** `margin-left:auto` in the component's own sheet puts the status at the right end of whatever card head row it is drawn in, so no section carries a place rule of its own; `title` carries nothing, because a tooltip is the face as well. A caller may not set `margin`, `margin-left` or `margin-right` on this row: the place belongs to the element, and a caller that needs the row to sit elsewhere moves the room, not the element.

**The shape.** `statusNode({ subject, value, data })` is a **plain function, not a component**, because that is how this page draws and how its checks read it: a chunk is materialised and the element tree it returns is read, and a component element is a node nobody renders there. It returns a `span.coreness-status` with `role="status"` and `aria-live="polite"`. The sheet is claimed as this package's own tag — `useStatusStyles`, `ensureStyles`, `data-plugin`, `data-plugin-css` — and this code never removes it.

**What a caller receives.** The chunk registers as `@coreness/dsh/client.status.js` and returns `{ statusNode, statusMark, useStatusStyles, STATUS_WORDS, statusWord, statusDetail }` (`plugins/page/client.status.js`). The second public drawing is the **mark of a connection** — one dot beside the name of the thing it is about, never in the corner, and never on a save (`plugins/page/client.status.js`) — and a card that draws a connection's state draws it with `statusMark` and no word. A card pulls the chunk with `require.async('./client.status.js')`, hands it one of the map's values and its own subject, and calls `statusDetail` where its answer arrives. That is the whole contract, and it is the shape every future element's contract is written in.

## What is not settled here

**Named, and the first rows drawn through the constructor.** The inventory names the elements, and the first of them are drawn: the entry draws its states through `statusNode`, the add row and its button are declared once in the page's own sheet and worn by both sections, the answer strip's reservation is one shared rule, the pill's radius is one name, and the button is one class the page declares once and every section wears beside its own. What is left of the private drawing is the rest of the list: each section still carries its own card, field and marker family — `coreness-mcp`, `coreness-qoder`, `coreness-gate`, `coreness-credits` — under its own numbers, and the **private** marks in §The elements are the migration's work list. Three divergences the rows left standing, named rather than smoothed: the Qoder's add control is a variant in its own actions bar (`.coreness-qoder-add`, a `.5px` dashed border against the shared button's `1px`), the answer strip's tone rules are still per-section, and the Qoder's controls carry no ring of the page's — the shared ring is taken back in that section's own sheet, left to the owner's word rather than folded silently — the migration's drawing takes those, not this card.

**What stands, and what it cannot see.** One committed check holds three of the rule's guards — *every class family the page draws is the inventory's, and every value a sheet reads is one the page declares*, the census check in `plugins/page/test/client.test.mjs`. It is named by its own name and not by a line: the runner prints the name, and the file moves under the correction of its own checks. The **family census** fails when a sheet declares a `coreness-<family>-` class the inventory does not name, and fails again when it read no family at all. The **declared-name check** fails when a sheet reads a `var(--coreness-*)` that no sheet declares — and the page carries **three** such names -- `--coreness-elevation`, `--coreness-news-strip` and `--coreness-pill-radius` (`plugins/page/client.js`), the first read by three sheets and the other two by the sheets of the sections that wear the elements they belong to — so it holds a floor too, because a scan that read nothing cannot pass it. Under both stands the **floor** itself: a chunk whose sheet yields no text fails, a chunk carrying a sheet id without a sheet or the reverse fails, and a scan that read fewer sheets than the entry pulls fails. Every chunk beside the entry carries a sheet but `client.hold.js`, which draws nothing and has none — `node scripts/page-css-read.mjs` counts the sheets it read on its own line. Two things that check cannot reach, named here rather than left to be found.
The **shell's own vocabulary** — the family-less class names its sheet declares, and the five the rows of §The elements took into that sheet for the elements the sections wear (`coreness-add`, `coreness-addRow`, `coreness-answer`, `coreness-button`, `coreness-dim`) — stands outside the rule the census reads, because the census reads families and these carry none, and the shell is not a card: its vocabulary is a divergence the inventory names rather than a defect it invents a family for. The names and their counts live in the batch's own comparison, which fails when one moves, and this file does not repeat them. And **the entry's private status passes the census**, because `coreness-status` is exactly the family the element declares: the guard sees families, so the deletion above is found by a reader and not by it. The shell is not a card, so its vocabulary is a divergence the inventory names rather than a defect it invents a family for; the decision it awaits is the one named above and it is not this file's to take.
